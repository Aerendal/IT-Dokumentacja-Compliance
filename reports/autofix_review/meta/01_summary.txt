=== Autofix V1 — Integracja Demo ===

CO ZOSTAŁO WDROŻONE:
  itdoc/fixes/ — nowy pakiet modułów autofix:
    markdown_model.py  — parser frontmatter + sekcji (stdlib only)
    rules.py           — 4 reguły V1 (2 safe_autofix, 2 report_only)
    planner.py         — generuje JSON plan zmian
    applier.py         — stosuje zmiany atomowo z backupem
    io_safe.py         — atomic write: temp→backup→rename, hash before/after
    engine.py          — orkiestracja: analyze/dry-run/apply
    report.py          — formatowanie wyników

  scripts/fix_docs.py         — główny CLI (--mode analyze/dry-run/apply)
  scripts/review_fix_plan.py  — podgląd planu JSON
  scripts/apply_fix_plan.py   — zastosowanie planu

PILOT: generated_templates/demo_case_01/ (3 pliki: A=valid, B=1 błąd, C=3 błędy)

REGUŁY V1:
  DOC.SECTION.MISSING     (safe_autofix=True)  — brak wymaganej sekcji → insert placeholder
  DOC.EMOJI.FORBIDDEN     (safe_autofix=True)  — emoji w pliku → strip
  DOC.FRONTMATTER.MISSING (safe_autofix=False) — brak frontmatter → report_only
  DOC.FRONTMATTER.NO_TITLE (safe_autofix=False) — brak title: → report_only

GWARANCJE:
  - dry-run nie zapisuje żadnych plików
  - każda zmiana ma rule_id, severity, safe_autofix flag
  - backup oryginalnego pliku przed zapisem
  - hash SHA-256 przed i po zmianie
  - drugi run (idempotencja): 0 safe changes po apply
